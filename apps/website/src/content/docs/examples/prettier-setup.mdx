The `prettier` namespace holds two blueprints:

- `prettier.config()` owns `.prettierrc.json` (owned mode — projitect rewrites it on every
  `pjt remodel`, so adjust it through options, not by hand), and merges the `format` script and the
  `prettier` devDependency into `package.json` (merge mode).
- `prettier.fix()` is a post-apply command. `pjt build` and `pjt remodel` run `prettier --write`
  after every file is written. `pjt inspect` runs `prettier --check` instead, never writes, and
  reports a failing check as drift with a nonzero exit.

In an initialized projitect project, install the configuration first. This step does not run
the formatter, so it works before Prettier is installed:

```bash
pnpm pjt add @projitect/blueprint-prettier --section config
pnpm pjt remodel
pnpm install
```

Then add the fix command and format the project:

```bash
pnpm pjt add @projitect/blueprint-prettier --section fix
pnpm pjt remodel
pnpm pjt inspect
```

## Options

```ts
prettier.config({
  semi: false,
  singleQuote: true,
  printWidth: 100,
  tabWidth: 2,
  trailingComma: "all" | "es5" | "none",
  proseWrap: "always" | "never" | "preserve",
})
```

Only the options you give are written to `.prettierrc.json`. The blueprint formats that file
with Prettier and pins the project's formatter to the same version, so nondefault indentation
and line widths stay clean after formatting. Invalid formatter options fail planning with
[`pjt.prettier.invalid-options`](/errors/pjt.prettier.invalid-options/).

`prettier.fix()` uses the shared CLI runner to find the project-local `prettier` executable;
it takes no package-manager option. The blueprint declares an exec permission for exactly
`prettier --write .` and `prettier --check .`. `inspect` runs only the check and never formats files.

`.prettierignore` is left to you; the `gitignore` blueprint does not manage it either.
