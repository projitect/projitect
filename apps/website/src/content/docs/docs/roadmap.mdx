The roadmap groups work into ordered tiers. Tier placement is a maintainer judgment and carries no
release dates. A version appears only where another page already states one.

## Shipped

Blueprints:

- `gitignore` — composable `.gitignore` sections
- `tsconfig` — managed `tsconfig.json`
- `vitest` — managed Vitest config
- `changesets` — managed Changesets config, scripts and devDependency

Engine and CLI:

- All four [ownership modes](/docs/concepts/ownership-modes/): region, merge, owned and seed
- `pjt init`, `pjt build`, `pjt remodel`, `pjt inspect`, `pjt explain` and `pjt add`
- `pjt inspect --json` — see [`pjt inspect`](/docs/cli/inspect/)

## Next

Next leads with outcomes for project owners. These are built and awaiting their first release:

- Versioned Markdown snippets for `AGENTS.md` and `README.md`
- Shareable agent skills
- The `react` blueprint, which creates a React + Vite + TypeScript app — see the
  [react-setup example](/examples/react-setup/)
- The `husky-lint-staged` blueprint, which manages the husky pre-commit hook, the lint-staged config
  and the devDependencies — see the
  [husky-lint-staged-setup example](/examples/husky-lint-staged-setup/)
- The `next` blueprint, which creates a Next.js App Router + TypeScript app — see the
  [next-setup example](/examples/next-setup/)
- The `prettier` blueprint, which manages the Prettier config and formats the project after
  `pjt build` and `pjt remodel` through a post-apply command — see the
  [prettier-setup example](/examples/prettier-setup/)
- `exec` post-apply operations in a blueprint's ChangeSet: `pjt build` and `pjt remodel` run the fix
  command, and `pjt inspect` runs the check and reports a failure as drift. See
  [the sandbox](/docs/concepts/sandbox/).

This outcome is planned and in progress, and is not built yet:

- Simple onboarding for humans, agents and CI, covering the upgrade, swap, remove and drift
  lifecycle

After those:

- The wider framework blueprint catalog
