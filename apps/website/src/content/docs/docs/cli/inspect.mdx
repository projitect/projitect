---
title: pjt inspect
description: Report drift between the project and its blueprints. Nonzero exit on drift.
---

```bash
pjt inspect [--json]
```

Compares the project against `.pjt.ts`. Exits **0** if in sync, **1** if drift is detected.
Built for CI.

## Exit codes

| Code | Meaning                                                                                                                                                                                                                |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0    | In sync, and every post-apply check passes. Prints `Project is in sync with blueprints. No changes needed.`                                                                                                            |
| 1    | Drift: a managed region or key was edited or is missing, an upgrade changed a blueprint's content, a blueprint left `.pjt.ts`, or a post-apply check failed. The drifted file or failing check is named in the output. |
| 1    | A blueprint declares a check its `exec` permissions do not name: `pjt.exec.command-not-permitted`. Inspect never passes such a check silently.                                                                         |

On exit 1 the human-readable output ends with ``Drift detected. Run `pjt remodel` to apply the blueprints.`` A script or agent runs `pjt remodel` and then `pjt inspect` again to confirm exit 0.

## Output

```text
↑ upgrade pjt:gitignore:macos 0.0.0 → 0.1.0
- remove pjt:gitignore:windows region from .gitignore   (blueprint left .pjt.ts)
~ modify .gitignore — region pjt:gitignore:macos content drift
+ create src/routes.generated.ts
  ok package.json
! check failed: pnpm lint (exit 1)
    src/index.ts: 3 problems
```

Five kinds of lines:

| Symbol  | Meaning                                                                                                                                                       |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `↑`     | Blueprint version changed since the lockfile was written. `pjt remodel` rewrites with the new version's content.                                              |
| `+`     | File missing or new region/key claim. `pjt remodel` will create it.                                                                                           |
| `~`     | File exists but managed content drifts. `pjt remodel` will rewrite to match.                                                                                  |
| `-`     | Lockfile records this region/key/file but no current blueprint claims it. `pjt remodel` will delete the orphan.                                               |
| `!`     | A post-apply check failed. The line names the command and its exit status, and the captured output follows, indented. `pjt remodel` runs the blueprint's fix. |
| (blank) | In sync.                                                                                                                                                      |

## Flags

| Flag     | Description                                                                                                                                                                                                          |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--json` | Emit structured JSON output `{ hasDrift, files, removals, upgrades, commands }`. Exit code stays 1 on drift — useful for CI tooling. An error is emitted as `{ "error": { ... } }` with the error's `id` and fields. |

### `--json` output shape

```json
{
  "$schema": "https://projitect.dev/schemas/inspect.v1.json",
  "hasDrift": true,
  "files": [
    {
      "path": ".gitignore",
      "status": "modify",
      "summary": "~ modify .gitignore — region pjt:gitignore:macos content drift"
    },
    { "path": "package.json", "status": "ok", "summary": "  ok package.json" }
  ],
  "removals": [
    {
      "_tag": "Region",
      "path": ".gitignore",
      "ownerId": "pjt:gitignore:windows",
      "commentPrefix": "#"
    }
  ],
  "upgrades": [{ "blueprintId": "pjt:gitignore:macos", "from": "0.0.0", "to": "0.1.0" }],
  "commands": [
    {
      "ownerId": "pjt:lint",
      "check": "pnpm lint",
      "status": "failed",
      "exitCode": 1,
      "stdout": "",
      "stderr": "src/index.ts: 3 problems\n"
    }
  ]
}
```

`commands` holds one entry per failing check, separate from `files`. `exitCode` is absent when the
check could not be started; `stderr` then carries the reason.

## Post-apply checks

A blueprint that declares a [post-apply command](/docs/authoring/) may give it a `check`. Inspect
runs each distinct check from the project root, in blueprint order, after the file comparison; a
check several blueprints declare runs once, and a command without a `check` is not run. Every check
must be covered by the blueprint's `exec` permissions, matched as exact strings, before any starts.
Checks must not change the project: inspect is read-only.

### Schema

Every `--json` output carries a `$schema` key naming the published contract:
[`/schemas/inspect.v1.json`](/schemas/inspect.v1.json), a [JSON Schema draft
2020-12](https://json-schema.org/draft/2020-12) document generated directly from the type
`pjt` encodes the output through — it can't drift from the code that produces it.

Versioning rule: new keys may be added within `v1` at any point (consumers should ignore
unknown keys — the schema itself allows additional properties). Renaming or removing a key is
a breaking change and ships as `inspect.v2.json` in a major release, alongside the existing
`v1` file.

## Use in CI

```yaml
- run: pnpm pjt inspect
```

Copy the full workflow from the [ci-integration example](/examples/ci-integration/). The job fails if any blueprint-managed file drifts. For richer CI tooling (Slack
notification with diff contents, GitHub Actions step summary, etc.), pipe `pjt inspect --json`
into your own formatter.

## What it doesn't check

- Files no blueprint claims (untouched and uncomplained-about).
- `seed`-mode files after first write.
- Content outside region markers in `region`-mode files.

This is intentional. projitect manages what it owns; you own everything else.
