---
title: pjt add
description: Install a blueprint package and splice it into .pjt.ts.
---

```bash
pjt add <package> [--section macOs,node,...]
```

Installs a blueprint package via your detected package manager and splices the corresponding import + call lines into `.pjt.ts` using the convention markers `// pjt:imports` and `// pjt:blueprints`.

## What happens

1. **Detect PM.** Walks for `pnpm-lock.yaml` → pnpm, `bun.lockb` → bun, `yarn.lock` → yarn, `package-lock.json` → npm. Falls back to npm.
2. **Install.** Shells out the PM's equivalent of `add -D <package>`. The output is forwarded to your terminal.
3. **Read package metadata.** Looks for a `"projitect"` field in the installed package's `package.json` (see [Authoring](/docs/authoring/) for the convention).
4. **Splice.** Inserts the import line between `// pjt:imports start/end` (deduped). For blueprint-set packages, inserts one call per section between `// pjt:blueprints start/end`. For single blueprints, inserts one call.
5. **Done.** Prints a summary. Run `pjt remodel` to actually apply the new blueprint to disk.

## Sections (for blueprint sets)

When the package declares `"type": "blueprint-set"`, you pick which sections to add. Three ways:

```bash
# 1. Explicit (any environment, deterministic)
pjt add @projitect/blueprint-gitignore --section macOs,node

# 2. Interactive (TTY only — projitect detects stdin and asks)
pjt add @projitect/blueprint-gitignore
#   → ? Pick sections to add (space to toggle, enter to confirm):
#        ◯ macOs
#        ◯ windows
#        ◉ linux
#        ◉ node
#        ◯ next
#        ...

# 3. Scripted-default (non-TTY, e.g. CI piping output)
echo "" | pjt add @projitect/blueprint-gitignore
#   → adds every section the package declares
```

Behavior is deterministic:

| Context                                     | Result                                            |
| ------------------------------------------- | ------------------------------------------------- |
| `--section <list>` provided                 | Use exactly that list                             |
| No `--section`, TTY (`process.stdin.isTTY`) | Interactive multi-select via `Prompt.multiSelect` |
| No `--section`, non-TTY (CI / piped)        | Add every section the package declares            |
| Interactive picker, nothing selected        | Add nothing                                       |

Pressing **Ctrl-C** during the interactive picker, or confirming with nothing ticked, leaves
`.pjt.ts` unchanged. The package stays installed, `pjt add` prints
`No sections selected; <file> was not changed.` and exits 0. Re-run with `--section` later.

The blueprint-set's `"callTemplate"` (e.g. `gitignores.{section}()`) is filled in per chosen section.

## Exit codes

| Code | Meaning                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------- |
| 0    | The package was installed and spliced, or the picker selected nothing and `.pjt.ts` is unchanged.                         |
| 1    | An error id was printed: install failed, markers missing, or no `projitect` metadata. The message names the next command. |

## Recipe: noninteractive (scripts and agents)

Pass `--section` and nothing prompts. Follow with `remodel` to write the files and `inspect` to
verify:

```bash
pjt add @projitect/blueprint-markdown --section agentsVerification,agentsCommits
pjt remodel     # exit 0 on success; nonzero with an error id on failure
pjt inspect     # exit 0: in sync; exit 1: drift (the file is named in the output)
```

The whole journey, including the agent path and the hand check of the interactive prompt, is on
[Install guidance and skills](/docs/journey/). See the [markdown-snippets example](/examples/markdown-snippets/) for the whole lifecycle,
including upgrades and removal.

## When the package doesn't have `"projitect"` metadata

`pjt add` installs the package, finds no `"projitect"` field in its `package.json`, and exits 1 with
[`pjt.add.metadata-missing`](/errors/pjt.add.metadata-missing/). `.pjt.ts` is left unchanged and
the package stays installed:

```text
Error [pjt.add.metadata-missing]: some-package was installed but has no `"projitect"` metadata in its package.json, so `pjt add` can't splice it into .pjt.ts. Import it in .pjt.ts by hand, then run `pjt remodel`.
```

Edit `.pjt.ts` manually, then run `pjt remodel`. To enable auto-splice for your own blueprint package, see [Authoring → Publishing](/docs/authoring/#publishing).

## Markers

`pjt add` writes between the **convention markers** (`pjt:imports`, `pjt:blueprints`). These are **not** managed regions in the lockfile sense — `pjt inspect` does not check them for drift. They're just splice anchors. If you delete them, `pjt add` fails with [`pjt.add.markers-missing`](/errors/pjt.add.markers-missing/) and tells you how to restore them.

The projitect blueprint's import (`import { pjt } from "projitect/cli"`) lives in a **different** marker pair — `pjt:projitect:imports` — which IS a managed region and IS drift-checked. Don't confuse them.
